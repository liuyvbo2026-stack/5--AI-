# 七人团队阶段 Codex／Claude Code 任务卡

前 48 小时由组长独立完成五步 MVP。团队接手时，先把 A–F 代号和实际 GitHub 用户名对应起来，再从 `docs/team-tasks.md` 拆出小 Issue。以下内容可复制给各自的 Codex Cloud 或 Claude Code；不得把旧故事原型当成新需求已经完成。

## 每个人的共同开工要求

请先读 `AGENTS.md`、`README.md`、`docs/PROJECT.md`、`docs/TEAM.md`、`docs/STRUCTURE.md`、`docs/HANDOFF.md` 和本人 Issue。检查当前代码、分支与未提交修改，再开独立 `feature/...` 分支。只解决 Issue 的验收条件；需要改其他人负责的共享文件时先在 Issue 说明并通知组长。完成后运行适用检查，记录人工验证、未验证项和改动文件，提交 PR；不得提交真实照片、密钥或邀请码。

## 组长

请核对五步 MVP 的真实状态、成员可投入时间和各 PR 的接口影响。为 A–F 各拆半天以内的可验收任务，明确优先级、依赖与负责人。审查 PR 时检查功能、自动测试、人工演示和敏感数据；决定合并顺序并更新交接记录。不要把未验证功能写成完成。

## A｜前端与集成

请以现有网页为起点，完成本人 Issue 的上传、风格选择、生成等待／失败或结果展示等前端交互。与 B 对齐 HTML 元素和视觉状态，与 D／F 对齐接口。只有评估现有版本无法满足需求且组长确认后，才提出框架迁移任务。提交能在手机和电脑上操作的截图或验证记录。

## B｜设计与体验

请检查五步流程是否易理解，并将本人 Issue 的视觉方案落实到 `design/` 与对应的 HTML／CSS PR。和 A 对齐交互标识与页面状态。验收包括手机布局、上传前后、生成中、失败和结果页；使用有许可的素材。

## C｜交付与回归

请复核实际运行环境与部署配置，在 `ops/` 记录必要步骤和非敏感结果。不要把旧故事部署说明直接照搬。各作者自测后，独立验证邀请码、双图、三风格、真实生成、预览下载和主要失败路径；记录复现步骤与部署限制。

## D｜真实生图

请先复现本人账号环境中的 Seedream 双图真实调用，再做本人 Issue 的服务端生成和错误处理。只从服务端环境变量取密钥。与 E 对齐风格配置输入，与 F 对齐邀请码状态；报告真实成功、成本来源、超时和未验证情况，不用示例图代替真实输出。

## E｜摄影风格

请在 `photography/` 维护三套风格的可执行配置、提示词版本与人工评测结果。与 D 对齐代码读取格式；用经授权素材做真实生成检查，只提交非敏感结论。区分有证据的风格效果和未验证的市场热度。

## F｜邀请码与业务校验

请优先完成本人 Issue 的邀请码原子占用、成功核销、明确失败恢复和不确定状态处理，以及必要输入校验。与 D 约定生成状态接口。风格 ID 先做确定性配置选择；照片分析、智能推荐和复杂 Skill Router 需要另开后续 Issue。
